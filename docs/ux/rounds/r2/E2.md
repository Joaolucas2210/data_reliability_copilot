## Scores per criterion, with evidence

**Nielsen**
- **N1 Visibility of system status: 8.**
  - Good: the Queued/Running cards say "updates automatically · last checked HH:MM:SS"; a polite live region announces status changes; there is a stale-data banner with Retry (`state-poll-refresh-error.png`); busy labels appear on buttons.
  - Gaps:
    - While validation runs, every step stays "pending" until the end, with no per-step progress and no elapsed time over about 78 s (`j6-val-_Running.png`).
    - The cancelled card says "Cancelled by **worker**" although the user cancelled (F3).
- **N2 Match with the real world: 7.**
  - Raw JSON blobs appear in the step details (snapshot step; on mobile, `mob-val-dark.png`).
  - Isolation detail strings are cut mid-word: " failed: connection…" and "ection failed: connection…" (F5).
  - Metric headers are snake_case (`cost_status`, `llm_calls_total`, `evals-d-light.png`).
  - The provider shows as "fake/—".
  - Timeline rows read "Investigation status investigation inv_…".
- **N3 User control and freedom: 7.**
  - Good: cancel exists and its confirmation has Go back; back/forward works; 404 pages offer exits.
  - Gaps: a role switch reloads and silently discards a typed review note (F4); Escape does not dismiss inline confirmations; jumping to cited evidence has no way back to the claim (F6).
- **N4 Consistency and standards: 8.** Status vocabulary, icons and tones are consistent everywhere. Small issues: the 404 page has two links to the same place ("Back to incidents" and "All incidents"); on mobile the tabs wrap onto two rows (`mob-inv-tabs-light.png`); the breadcrumb label "Incident" is generic.
- **N5 Error prevention: 8.**
  - Good: confirmations for cancel, approve, reject and start-another; the reject note is required and whitespace is trimmed; double-click guard; idempotency key; disabled buttons show their reason.
  - Gaps: "also mark the incident as resolved" is pre-checked for an irreversible approval; nothing warns when approving a recovery that was never sandbox-validated (F8); role switch drops data.
- **N6 Recognition rather than recall: 7.**
  - The Validate action and the VERIFIED status live inside the non-default Recommendation tab. The approver deciding at "Human review" cannot see the validation result without switching tabs (F7).
  - Pages identify entities by ID, not name.
  - Citation jumps lose context (F6).
- **N7 Flexibility and efficiency: 6.**
  - The incident list (30+ rows) has no search or sort. The status filter is component state, so it is not in the URL (NOT VERIFIED that back loses it).
  - There are no shortcuts. The investigation page needs 12 Tab presses to reach the first citation.
- **N8 Aesthetic and minimalist design: 7.**
  - The investigation page is about 7200 px tall on desktop (`myinv-d-light.png`): 19 evidence cards, all expanded, push the usage and tool-call information far down.
  - The validation snapshot step dumps raw hashes.
- **N9 Help users recover from errors: 8.**
  - Good: clear, non-technical messages, a Retry button, inline action errors next to the control, and 404s with exits.
  - Gap: the start-action error says "Retry…" but gives no retry affordance beyond the same button. After the error, focus is on `<body>` (F1).
- **N10 Help and documentation: 7.** Good inline explanations: what each step proves, the caveat on citations, "model's own label, not calibrated". There is no help, glossary or onboarding.

**Shneiderman**
- **S1 Consistency: 8.** Same as N4.
- **S2 Universal usability: 7.** Dark mode, 320 px reflow, reduced motion and axe are all clean. But keyboard and screen-reader focus is lost on every detail page (F1). The `role="alert"` "Access denied" box fires on every investigator or viewer page load (F9). Citation chips are about 22 px tall on mobile.
- **S3 Informative feedback: 8.**
  - Good: announcements, busy states, the decision panel.
  - Gaps: after approving, the announcer's final text is "Investigation is now completed." (the "Decision recorded…" message is overwritten); "Cancelled by worker" is misattributed.
- **S4 Dialogs that yield closure: 8.**
  - Good: start lands on the new investigation; cancel gives a card with a link back; a decision gives the "Decision recorded" panel with focus and a link to the incident, whose status reads Resolved.
  - Gap: when a validation finishes, the page offers no next step (back to the investigation or review), only the breadcrumb (F2).
- **S5 Prevent errors: 8.** Same as N5.
- **S6 Permit easy reversal of actions: 6.**
  - Decisions "cannot be undone".
  - A resolved incident shows "no new investigations can be started" and has no reopen action.
  - A cancelled investigation "cannot be resumed".
  - Confirmations exist, but no undo window or reopen path exists anywhere, and the pre-checked "resolve" box widens the blast radius of one approve.
- **S7 Users in control: 7.** The role select reloads instantly without warning. Focus jumps to `<body>` on async renders. Polling is unobtrusive and good.
- **S8 Reduce short-term memory load: 6.** The approver must remember the validation result while deciding (F7). The citation→evidence jump has no return path (F6). The long single page forces scrolling between claims and evidence. Raw IDs have to be compared across screens (timeline, breadcrumb).

**UI**
- **U1 Visual hierarchy: 8.** Clear H1, status pills and cards. The decision area sits in the middle of a very long page, and the evidence list dominates.
- **U2 Typography and legibility: 8.** Legible in both themes. There is a lot of small monospace text, and the JSON blobs wrap badly on mobile.
- **U3 Spacing and alignment: 8.** Consistent. The tabs wrap to two rows at 390 px.
- **U4 Component consistency: 8.** ActionButton, pills, states and tables are uniform. The 404 has redundant links.
- **U5 Responsiveness: 8.** Nothing scrolls horizontally at 320 or 390, and tables stack. Mobile pages are very long, the validation page reaching about 5250 px.
- **U6 Contrast and use of colour: 9.** axe is clean in both themes, and colour always comes with an icon and text.
- **U7 Keyboard, focus and semantics: 6.**
  - Good: skip link; Tab order; tabs follow the WAI-ARIA pattern (arrows, End); a visible focus ring; confirmation focus management.
  - P1: on incident, investigation and validation pages, focus lands on the loading H1, which is then unmounted, so `document.activeElement` becomes BODY (`focus.mjs` output).
  - Also: the gallery has the `landmark-unique` issue, and Escape does not close confirmations.
- **U8 Clarity of copy: 7.** "Cancelled by worker", truncated details, snake_case headers, "Access denied" wording for a role-information state, and "fake/—".
- **U9 Feedback and micro-interactions: 8.** Busy labels, spinners, inline errors and the stale banner. No running-step progress.
- **U10 Motion and perceived performance: 9.** Only a functional spinner, which `prefers-reduced-motion` disables. Pages load fast (about 0.1 s). Validation takes about 78 s with no progress, which is covered under N1.

## Limitations
- The Chromium in dev mode runs React StrictMode, which double-fetches. I ignored this when interpreting the mocks.
- Other evaluators load the same API at the same time. One of my mobile captures caught a transient Loading state, which I re-shot (`mob-*.png`).
- The worker was fast for investigations (about 3 s), so I verified the Running and cancel-while-running UI partly with mocked responses.
- J7 tested **approve** on my fixture. **Reject** was tested only up to validation and confirmation, so the persisted reject outcome was not observed.
- On the shared investigation, an approver confirmation was opened and dismissed with Go back. Nothing was mutated.
- No real assistive technology was used.
- Scores are my calibrated judgement under the brief's operational rubric.
