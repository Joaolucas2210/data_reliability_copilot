# E4: Accessibility, contrast, motion & micro-interactions (round r2, commit f99dd93)

All evidence comes from the rendered app at http://127.0.0.1:5173, driven by Playwright and axe-core 4.x (tags wcag2a/2aa/21a/21aa/22aa + best-practice). Scripts and screenshots are in this directory (`shots/` holds 140+ PNGs; the raw axe output is in `axe.json`).

## 1. Coverage
- **axe sweep** (`axe_sweep.mjs`) covered 13 screens (health, incidents, two incident details, two investigations including every tab, validation, evaluations, gallery, unknown route, and three 404 ids) × light/dark × desktop 1440×900 / mobile 390×844 × viewer, plus investigator/approver on the entity screens. It also covered loading (4 s route delay), API 500 and empty-filter states on 4 screens × 2 themes × 2 viewports. **Result: 0 violations everywhere except the gallery** (`landmark-unique`, 7 nodes, all 4 theme/viewport combinations). There were no colour-contrast, target-size or ARIA violations in any state, theme or viewport.
- **Keyboard-only runs** (`focus.mjs`, `tabfocus.mjs`, `j4j8.mjs`, `j6j7.mjs`, `misc.mjs`), with a MutationObserver recording every live region / role=status / role=alert change:
  - J4 (my incident inc_01a121acdd0423746e20): Start → queued (28 s) → running → awaiting review.
  - J8: Start another (confirm) → cancel (confirm) → cancelled. I also tested back/forward and the role switch.
  - J6: validated prop_01a121acd952bb225859 → val_01a121b838e9fbd828d8 (queued → running → passed in about 51 s).
  - J7: rejected with an empty note (validation), then approved with a note.
- **Focus visibility, light and dark** (`focusvis.mjs`): checked on tab, cite chip, textarea, checkbox, primary/danger buttons, breadcrumb, nav, select, tabpanel and scroll region.
- **Reflow** (`reflow.mjs`): 320 px; 720×450 (equivalent to 200 % zoom of 1440×900); WCAG 1.4.12 text spacing at 320 px and 1440 px.
- **Reduced motion** (`motion.mjs`).

## 5. Findings

**F1 (P1) Focus is dropped to `<body>` after SPA navigation to incident, investigation or validation pages, and after Back/Forward**
- **Screen/state:** J3-J8, both themes, all roles, desktop and mobile.
- **Problem:**
  - At navigation the App focuses the loading-state `<h1>` ("Incident" / "Investigation" / "Recovery validation"). That h1 is unmounted when data arrives and the new h1 is never focused.
  - Measured: `incident detail (30ms): h1 "Incident"` → `(settled): body`. The same happened for the investigation link, Back, Forward, Start investigation → investigation page, and Validate → validation page.
  - The heading is not announced and screen-reader users lose their place. Chrome's sequential-focus start point lets the next Tab land roughly right, which hides the problem for sighted keyboard users.
- **Principles:** WCAG 2.4.3, 4.1.3 (spirit); N3, S7, U7.
- **Evidence:** focus.mjs output; j4j8.mjs ("states … active: body"); j6j7.mjs.
- **Fix:** keep a single persistent `<h1>` per page (render the entity title in place of the loading title rather than swapping elements), or re-run the focus effect when the page's h1 changes after load. Pages should own their focus target.

**F2 (P2) Focus is lost during and after async actions**
- **Screen/state:** Approve/Reject confirm, Start, Cancel, Validate.
- **Problem:**
  - The confirm button gets `disabled` while busy and Chrome blurs it (`busy focus: body`).
  - On a failed action (500 mocked), focus stays on `<body>` and the error is reachable only by browsing.
  - After a successful cancel, the Cancel card unmounts and focus goes to body.
  - In J4, the Cancel button disappears when the status moves to awaiting review.
- **Principles:** 2.4.3; S3, U7, U9.
- **Evidence:** j6j7.mjs; misc.mjs; shots/action-error.png; shots/j7-busy.png.
- **Fix:**
  - Use `aria-disabled` + `inFlight` guard instead of `disabled` while busy.
  - On error, focus the error message or keep focus on the button.
  - After cancel, or when a polled status replaces the card, move focus to the new card heading.

**F3 (P2) `role="alert"` used for static permission notes**
- **Screen/state:** viewer/investigator investigation page (review card), restricted evidence items, gallery (4 alerts on load).
- **Problem:**
  - AccessDenied is a static explanation, but as an assertive alert it interrupts on page load.
  - In J4 it fired at the same moment as the polite "Investigation is now awaiting review." announcement and can cut it off.
  - Restricted evidence renders one alert per item.
- **Principles:** 4.1.3, ARIA APG; S2, U7.
- **Evidence:** live log in j4j8.mjs ("32s alert: ⊘ Access denied…" next to the announcer); tabfocus.mjs (alerts: 1); gal.mjs (alerts 4).
- **Fix:** drop the role (or use `role="note"`) for permission states rendered as part of the page. Keep `alert` only for errors caused by a user action.

**F4 (P2) Status filter gives no screen-reader feedback and is not remembered**
- **Screen/state:** #/incidents, J2.
- **Problem:** after changing the filter (ArrowDown or selectOption "investigating"), nothing was written to any live region (`live: []`), including the empty "No incidents" result. The filter resets to "All statuses" after opening an incident and pressing Back.
- **Principles:** 4.1.3; N1, N3, N7, S8.
- **Evidence:** focus.mjs; misc.mjs ("filter after back: ''").
- **Fix:** `announce("N incidents shown" / "No incidents for this filter")` after load; keep the filter in the hash (`#/incidents?status=…`).

**F5 (P2) Evaluation comparison hides most metrics off-screen**
- **Screen/state:** #/evaluations, desktop and 200 % zoom (J9).
- **Problem:**
  - The "Systems compared" table has 23 columns, 4021 px wide in a 1102 px region.
  - Only 9 columns are visible at 1440 px. diagnosis_accuracy, citation_precision, unsupported_claims_total and the others are off-screen, with no scrollbar visible in the rendered screenshot and the System column not sticky.
  - Headers are raw snake_case.
  - Per-scenario rows such as "Expected Diagnosed / Got Diagnosed → wrong" give no reason.
- **Principles:** N1, N2, N6, N8, S8, U5.
- **Evidence:** shots/evals-systems-desktop.png; evw.mjs / evd.mjs measurements.
- **Fix:**
  - Transpose the table (metrics as rows, systems as 3 columns), with human labels and units.
  - Lead with the key metrics.
  - Explain why a scenario is "wrong" (e.g. wrong cause).

**F6 (P2) Role (dev) select reloads the page on any change, including arrow keys**
- **Screen/state:** top bar, J8 role switch.
- **Problem:** ArrowDown on the focused select immediately calls `location.reload()`. Focus goes to body and any typed review note is lost.
- **Principles:** WCAG 3.2.2 On Input; S7, N3.
- **Evidence:** focus.mjs ("role select ArrowDown -> reloaded: true … active: body").
- **Fix:** add an "Apply" button, or refetch views without a reload; restore focus to the select.

**F7 (P3) Gallery semantics**
- **Problem:**
  - The gallery h1 has no tabindex, so after nav focus stays on the nav link.
  - There are 4 h1s, because the embedded screens render their own h1.
  - axe reports `landmark-unique` on 7 nodes (repeated section/region names).
- **Principles:** 1.3.1, 2.4.6; N4, U7.
- **Evidence:** focus.mjs ("gallery nav -> a 'Component gallery'"); axe.json; gal.mjs.
- **Fix:** use PageTitle; demote the embedded page titles (heading-level prop); give fixture regions unique names.

**F8 (P3) Inline confirmations ignore Escape**
- **Screen/state:** all confirmations.
- **Problem:** Escape leaves the confirmation open with focus unchanged.
- **Principles:** N3, S6.
- **Evidence:** j4j8.mjs.
- **Fix:** on Escape, behave as "Go back" (return focus to the trigger).

**F9 (P3) aria-disabled actions are weakly differentiated**
- **Screen/state:** viewer Start/Validate/Cancel.
- **Problem:** the disabled look is only `opacity:.6`, so a primary button stays bright blue (white text on about #7795e8, roughly 3:1). It reads as enabled-but-faded. The reason text ("⊘ Requires the investigator role") is present and programmatically linked, which is good.
- **Principles:** U6, N4.
- **Evidence:** shots/ariadisabled-light.png; focusvis.mjs.
- **Fix:** use a neutral style (surface background, muted border) for aria-disabled, plus a lock icon.

**F10 (P3) Text spacing (1.4.12) causes small page-level horizontal overflow at 320 px**
- **Screen/state:** incident detail (docW 322) and gallery (334).
- **Principles:** 1.4.12, 1.4.10; U5.
- **Evidence:** reflow.mjs output.
- **Fix:** allow the offending link/heading to wrap (`overflow-wrap:anywhere` / `min-width:0`).

**F11 (P3) At 200 % zoom (720 CSS px) tables stay tabular and very cramped**
- **Screen/state:** incidents list and the other tables.
- **Problem:** the incident title column is about 60 px wide with one word per line, and the other columns need horizontal scrolling. Stacking only starts at 600 px or below.
- **Principles:** U5, S2.
- **Evidence:** shots/reflow-zoom200-incidents.png.
- **Fix:** raise the stacked breakpoint (e.g. ≤ 800 px) or give the title column a minimum width.

**F12 (P3) "Cancelled by worker" after the user cancelled**
- **Screen/state:** cancelled investigation.
- **Problem:** the text names the actor that applied the cancellation, not the person who requested it.
- **Principles:** N2, U8.
- **Evidence:** shots/j8-cancelled.png.
- **Fix:** show who requested the cancellation, e.g. "Cancelled at …, requested by dev:investigator".

**F13 (P3) Evidence navigation and typography**
- **Problem:**
  - After a citation chip moves focus to the evidence item (focus ring is visible, shots/kb-cite-target-light.png), there is no "back to claim" link.
  - The "Collected" value is rendered in a larger sans font among mono values.
- **Principles:** N3, U2, U4.
- **Fix:** add a return link; use consistent value styling.

**F14 (P3) Raw JSON step detail on mobile**
- **Screen/state:** validation run at 390 px.
- **Problem:** the snapshot step dumps a long JSON blob (about 30 wrapped lines).
- **Principles:** N8, U2.
- **Evidence:** shots/j6-result-mobile-dark.png.
- **Fix:** summarise ("6 tables copied, hashes match") and put the JSON behind a `<details>`.

**F15 (P3) Health "26 open" link opens the unfiltered list**
- **Problem:** the link opens all statuses, including resolved and dismissed.
- **Principles:** N2, N6.
- **Evidence:** shots/health-light-desktop-viewer.png.
- **Fix:** link to a filtered list.

**F16 (P3) Programmatic focus targets have no visible indicator**
- **Problem:** `[tabindex="-1"]:focus{outline:none}` hides focus on h1 and "Decision recorded" h2. Sighted keyboard users get no cue where focus landed.
- **Principles:** 2.4.7 (advisory); U7.
- **Evidence:** shots/j7-decision-dark.png.
- **Fix:** show a subtle focus style (e.g. underline or left bar) on programmatically focused headings.

## 6. Limitations
- No real assistive technology was used. Announcement behaviour is inferred from the DOM, live-region roles and focus.
- Chromium headless only (no Firefox or Safari). Headless may hide overlay scrollbars, which affects F5's "no visible cue".
- 200 % zoom was emulated with a 720×450 viewport.
- Only one live J4/J6/J7/J8 run each (mutable fixtures). Intermediate states came from real worker timing (queued 28 s, validation 51 s), not mocks; busy and error states were mocked with page.route.
- No restricted evidence exists in live data, so that state was checked only on the gallery fixture.
- 403-on-GET was not mocked.
- Side effects on my fixtures:
  - inc_01a121acdd0423746e20 now has inv_01a121b7429ede45c318 (awaiting review) and inv_01a121b7c1eeafe2e184 (cancelled).
  - Proposal prop_01a121acd952bb225859 was validated (val_01a121b838e9fbd828d8, passed).
  - inv_01a121acd952bb225859 was approved with a note; its incident is resolved.
