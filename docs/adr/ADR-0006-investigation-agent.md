# ADR-0006: One LangGraph investigation agent with explicit state, bounded tools and enforced citations

- **Status:** Accepted (provisional for the model choice, 2026-10-09). The workflow is accepted. The live model choice is unvalidated: no API credentials were available, so no live evaluation ran.
- **Deciders:** project owner (Staff Engineer role)

## Context

Investigations must turn incident evidence into a diagnosis where facts, hypotheses and recommendations are separate. Every factual
claim must reference existing evidence, and the agent must abstain when evidence is insufficient. Runs must be bounded
(steps, tools, tokens, time, cost), resumable after crashes, and paused for human review. Logs may contain prompt injection.
Tests and demos must run without credentials.

## Alternatives

1. **Single LLM call with all evidence.** Cheap, but the model can't ask for more evidence and has no explicit states to audit.
2. **Free-form ReAct loop / SDK tool runner.** Flexible, but states, limits and the human gate end up implicit in a while-loop.
3. **Multi-agent (planner/investigator/critic).** More moving parts and more cost before a single-agent baseline exists.
4. **One LangGraph `StateGraph` with explicit nodes + Postgres checkpointing** (chosen).

## Decision

- Graph (`agent.build`): `receive → gather → hypothesize ⇄ seek_more → conclude → verify → (propose) → persist_for_review
  → human_review (interrupt) → record`. Each node has a single job. `gather` collects baseline evidence without the LLM.
- State is a `TypedDict` (`agent.State`) checkpointed by `PostgresSaver` in the `app` DB, with `thread_id = investigation_id`.
  `agent.run` resumes from the last checkpoint, and `agent.review` resumes the interrupt with `Command(resume=…)`.
- Limits (`agent.LIMITS`): 3 rounds, 20 tool calls, 6 LLM calls, 120k input tokens, 300 s wall time, US$1.00. Limits are checked before
  each LLM call. Hitting one forces `outcome="abstained"` with the limit named. The agent never guesses past a limit.
- Output contract `domain.Diagnosis`: outcome (`diagnosed|abstained|no_fault_found`), summary, `observed_facts`
  (each with `evidence_ids` + verbatim `quote`), hypotheses (supported/refuted/inconclusive with supporting and contradicting ids),
  contradicting evidence, missing information, estimated scope, next step, optional recovery (allow-listed playbook only),
  and `self_reported_confidence`, which is explicitly **not** a calibrated probability.
- `citations.verify` checks two levels deterministically. (1) Every cited id was collected in this investigation. (2) Each
  fact's quote is a whitespace-normalised substring of a cited evidence. Facts that fail are removed and reported.
  A supported hypothesis citing a missing id becomes inconclusive. If a `diagnosed` outcome has no surviving fact or
  supported hypothesis, it is downgraded to `abstained`. Passing both checks does **not** prove that the statement follows from the quote.
- Tools (`tools.py`): 11 read-only functions. Datasets are allow-listed, warehouse access goes through `copilot_reader`, and every
  tool is scoped to the incident's run (the LLM never chooses a run or path). Row/line caps apply and PII columns are dropped.
  `tools.call` is idempotent on (investigation, tool, args), so replay returns stored evidence. Proposal ids are deterministic.
- Prompt injection: evidence is rendered inside `<evidence>` blocks labelled untrusted data. The system prompt forbids following
  instructions found in it. DUP scenarios plant "ignore all previous instructions…" in the ingestion log.
- Provider adapter (`llm.py`):
  - `fake` is a hand-written deterministic policy over the same evidence. It is labelled `mode=fake`, and its tokens and cost are `None`/`unknown`.
  - `anthropic` uses `claude-opus-5-5` by default, following current Anthropic guidance. It calls `messages.create` with
    `output_config.format` json_schema (generated by `strict_schema`) and `effort: "medium"`, then validates with pydantic.
    Refusal and `max_tokens` stop reasons raise errors.
  - Cost is list price × measured tokens, labelled `estimated`. An unknown cost is `None`, never 0.
  - Fallback happens only if `DRC_LLM_FALLBACK_MODEL` is set (off by default). It is logged per call (`fallback_from`, reason) and
    counted in usage. Server-side `fallbacks` was considered and not used: it can't be validated without credentials here, and the brief requires fallback to be evaluated separately.
- MCP is a later step. It would expose the same `tools.TOOLS` functions, keeping their contracts and limits.

## Trade-offs

- Structured output instead of native tool-use blocks. The runtime, not the model, executes tools and enforces limits. The cost
  is that tool arguments travel as a JSON string (`args_json`) and are validated at runtime.
- Verbatim-quote grounding is strict and cheap, but it rejects valid paraphrases. That is deliberate.
- A deterministic fake makes CI meaningful for plumbing, but meaningless for model quality (ADR-0008).

## Risks

- **No live run yet.** Schema acceptance by the API (e.g. `maxLength` on lists, `Literal` enums) and real token, latency and cost
  figures are unverified.
- Checkpoint replay re-executes a node that crashed mid-way. External effects are safe only because tools are read-only and
  idempotent, and DB writes use upserts or validated transitions.
- An LLM may still be swayed by injected text. Citation enforcement limits the damage to unsupported claims, but doesn't stop it.

## Evidence

- DUP-01 (fake): 8 tool calls, 3 LLM calls. 5/5 facts supported, citation precision 1.0. H1 duplication supported, H2 transformation
  change refuted. A proposal was created and the run paused at `awaiting_review`.
- `tests/test_unit.py`: a paraphrased quote leads to `abstained`, and an unknown id makes the hypothesis inconclusive.
- `tests/test_integration.py`: crash after `gather` then resume, and each (tool, args) is executed once. Evidence contains no scenario labels.
- Anthropic API usage per the bundled Claude API skill (model table cached 2026-10-06); SDK `anthropic==1.12.1` exposes `output_config`.

## Revisit when

- Credentials are available. Run `drc eval --split dev --provider anthropic`, compare effort levels and models on accuracy, unsupported
  claims and cost per diagnosis, then record the chosen model here.
- Unsupported-fact rate (live) is above 10%, or abstention on INS scenarios is below 1.0. Revise the prompt (bump `PROMPT_VERSION`).
- Investigations regularly hit `max_llm_calls` or `max_wall_s`. Revisit limits with data.
- A second consumer (IDE, chat) needs the tools. Expose them over MCP.
